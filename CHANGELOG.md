# Изменения

## 0.20.0 — 2026-10-31
- Web Push (задача 4.5, концепт §5 «Push»: VAPID для PWA — Android, iOS 16.4+ и десктоп) — одно напоминание в день. Уведомление приходит к назначенному времени в поясе ученика: заголовок — задание дня («Offerly: Занятие · Артикли», «Offerly: Репетиция интервью», «Offerly: Программы ещё нет»), тело — письмо дня, сколько карточек ждёт повтора, серия, сколько минут осталось до недельной цели, дни до собеседования; клик открывает приложение (уже открытое окно — в фокус). Содержимое — из тех же данных, что и письмо (`collectDigest`), ничего не выдумывается; если занятие дня к назначенному времени уже пройдено, напоминание не приходит (день помечается `skipped:done`). Правила те же, что у письма: окно `SEND_WINDOW_MINUTES = 180`, не больше одного в день, пропущенный день не досылается, новое уведомление заменяет непрочитанное вчерашнее (`Topic: offerly-daily`), в push-службе живёт столько же, сколько окно. Каналы независимы: время напоминания — `push_settings.push_at`, письма — `profiles.notify_at`.
- Протокол (`functions/_lib/push.ts`) целиком на WebCrypto, без npm `web-push`: подпись VAPID — ECDSA P-256, JWT ES256 с `aud` = источник push-службы и сроком 12 часов (RFC 8292); тело — ECDH P-256 + HKDF-SHA-256 + AES-128-GCM по схеме `aes128gcm` с эфемерной парой и случайной солью на каждое сообщение (RFC 8291, RFC 8188). Пара ключей VAPID берётся из секретов `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` (base64url: открытый 65 байт без сжатия, закрытый 32), а если их нет — создаётся один раз при первом обращении и хранится в `app_settings` (ключ `vapid`), поэтому Pages-приложение и cron-Worker подписывают одними и теми же ключами без ручной настройки; смена ключей обнуляет подписки. `sub` — секрет `VAPID_SUBJECT` или адрес приложения. Исчезнувшая подписка (404/410) удаляется, прочие отказы записываются в `last_error` подписки. Миграция 0018: таблицы `push_subscriptions` (endpoint уникален — переподписка того же браузера обновляет строку), `push_settings`, `app_settings` — только добавление.
- Worker `offerly-digest` теперь делает оба прохода независимо (`runAll`: письмо и напоминание, сбой одного не мешает другому); `GET /` — состояние с блоком `push` (откуда ключи: env | db | pending; сколько пользователей и в каких состояниях), `POST /run` отдаёт оба отчёта. `GET /api/health` показывает `push: env | db | pending`.
- API: `GET /api/push` — открытый ключ VAPID для PushManager, время, включено ли, состояние на сегодня, заметка последней попытки (`sent`, `sent:1/2`, `skipped:done`, `skipped:late`, `skipped:no_subscriptions`, `error:…`), когда следующее, устройства (браузер · система, подписано, последняя доставка, последняя ошибка — без endpoint и ключей); `PUT /api/push {pushAt}` — включить, переставить, выключить (подписки остаются); `POST /api/push/subscribe {endpoint, keys:{p256dh, auth}, userAgent?, pushAt?}` — подписка браузера (`push_invalid` 400), при первой подписке напоминание включается на время письма или `07:30`; `DELETE /api/push/subscribe {endpoint}` — отписать устройство, последнее выключает напоминание; `POST /api/push/send` — прислать сейчас на все устройства, день не отмечается (`push_no_subscriptions` 404, `push_failed` 502). Неверные ключи в секретах — `vapid_invalid` 503.
- Экран: карточка «Напоминание» на главном (после «Ежедневного письма»): строка состояния («Сегодня напоминание не понадобилось — занятие уже было пройдено; следующее 1 ноября 2026 г. в 07:41»), кнопка «Включить на этом устройстве» (разрешение браузера → подписка ключом сервера → сервер), «отписать это устройство», время с «Включить / Переставить», «выключить», «прислать сейчас» (показывает, что ушло: заголовок и текст), список устройств с последней доставкой и ошибкой; честные пояснения, когда напоминания здесь недоступны: нет HTTPS, нет Web Push в браузере, уведомления запрещены в настройках сайта, iPhone и iPad без установки на экран «Домой» (с инструкцией). Service worker: `public/push-sw.js` подключается к сгенерированному `sw.js` через `workbox.importScripts` — обработчики `push` (без полезной нагрузки — общий текст), `notificationclick`, `pushsubscriptionchange` (переподписка тем же ключом и отправка на сервер).
- Тесты `tests/push.test.ts` (22): base64url, ключи VAPID и проверка формы, JWT (разбор, срок, проверка подписи открытым ключом, чужой ключ), ключи из секретов и из базы (создаются один раз), шифрование — расшифровка «браузером» по RFC независимой записью (структура заголовка, новая соль и пара на каждое сообщение, кириллица, чужой ключ, неверные ключи подписки, предел нагрузки), `sendWebPush` (заголовки, 201 / 410 / 404 / 429 / сбой сети), текст напоминания (занятый день, без программы), проход расписания (пора на два устройства / рано / без дублей; занятие пройдено; поздно; устройств нет; 410 удаляет, 429 в `last_error`, ни одной доставки — failed; «прислать сейчас» без отметки дня), разбор тела подписки, подписи устройств, маршруты API (401, ключ и health, подписка и включение, повтор без дублей, своё время, PUT, отписка до последнего устройства, время по умолчанию, отправка 404/200/502), D1-хранилище на миграциях, Worker на seed первого пользователя по настоящему SQL (напоминание Юрию в 07:50 Алматы, статус без адресов, `/run` с обоими отчётами), service worker с подставным `self` и подключение в vite.config; `tests/push-client.test.ts` (4): поддержка по браузерам и iOS, ключ для `applicationServerKey`, строки состояния. Playwright на dist с route-моком: карточка без устройств (кнопка включения), с устройствами — «прислать сейчас», перестановка времени, ошибки доставки, тёмная тема на телефоне. Дымовая проверка — аннотация `push` в Deep check.

## 0.19.0 — 2026-10-31
- Ежедневное письмо (задача 4.4, концепт §5 «Почта»: cron-Worker + Resend). Одно письмо в день в назначенное время в поясе ученика: задание дня по программе (формат, тема, письмо, минуты и причина выбора темы; пройденный день — с баллом; без программы — как её составить), сколько карточек ждёт повтора в журнале, готовность с уровнем и целью, серия и заморозка, минуты недели, обратный отсчёт до собеседования, ход программы, кнопка «Открыть Offerly». Содержимое считают те же модули, что и экраны (`program.ts`, `cards.ts`, `dashboard.ts`) — ничего не выдумывается. Текст и HTML в цветах дизайн-проекта (графит, бумага, янтарная полоса готовности), без эмодзи; тема письма — «Offerly, 2 ноября: занятие · Союзы и инверсия».
- Расписание (`functions/_lib/digest.ts`): время — `profiles.notify_at` (HH:MM, NULL — выключено; у первого пользователя из seed — 07:41). Pages Functions не умеют расписание, поэтому письма рассылает отдельный Worker `workers/digest` (та же база D1, тот же `RESEND_API_KEY`) по cron `*/15 * * * *`: перебирает включённых, шлёт тем, у кого в их поясе наступило назначенное время и не прошло больше `SEND_WINDOW_MINUTES = 180` (письмо «на утро» в десять вечера не нужно); день отмечается в `profiles.digest_sent_on`, поэтому за день уходит не больше одного письма; пропущенный день (Worker не работал) помечается `skipped:late` и не досылается; отказ Resend — `error:…` с отметкой дня, без повторов каждые четверть часа. Миграция 0017: `digest_sent_on`, `digest_sent_at`, `digest_note` в `profiles` — только добавление. Worker отвечает `GET /` состоянием без адресов (версия, база, почта, cron, сколько пользователей ждут письма и в каком состоянии), `POST /run` с заголовком `x-digest-key` = секрет `DIGEST_KEY` — прогон вне расписания.
- Деплой: шаг «Deploy digest Worker (cron)» в workflow — `wrangler deploy --config workers/digest/wrangler.toml` с подстановкой id базы и передачей `RESEND_API_KEY`; сбой шага (например, токену не хватает права Workers Scripts: Edit) не валит деплой приложения — предупреждение в аннотации `digest deploy`. Дымовая проверка — аннотация `digest` в Deep check: коды маршрутов без cookie и строка состояния Worker.
- API: `GET /api/digest` — время, включено ли, пояс и местное время, состояние на сегодня (`off | early | due | late | sent`), дата последней отметки, когда следующее письмо, настроена ли почта, предпросмотр сегодняшнего письма (тема, текст, число карточек; `?preview=0` — без него); `PUT /api/digest {notifyAt: "HH:MM" | null}` — включить, переставить или выключить (`notify_invalid` 400); если назначенное время сегодня уже прошло, день отмечается сразу и первое письмо придёт завтра; `POST /api/digest/send` — прислать сейчас, вне расписания (`mail_not_configured` 503, `mail_failed` 502). Переменная `APP_URL` — адрес для ссылок в письмах.
- Экран: карточка «Ежедневное письмо» на главном (после «Достижений»): строка состояния («Сегодняшнее письмо отправлено; следующее 1 ноября 2026 г. в 07:41», «Время наступило — письмо уйдёт в ближайшие 15 минут», «окно отправки прошло»), пояс и местное время, поле времени с кнопкой «Включить / Переставить», «выключить», «прислать сейчас», предупреждение, если почта на сервере не настроена, и «Показать сегодняшний текст» — тот же текст, что уйдёт в письме.

## 0.18.0 — 2026-10-31
- Контрольный срез (задача 4.3, концепт §2 «Промежуточный срез»): раз в две недели по программе — укороченный вариант стартового теста. Тот же конвейер `assessment.ts`, обобщённый по виду теста: `kind = checkpoint`, восемь адаптивных заданий вместо двенадцати (исправление на 3 и 6), затем чтение с двумя вопросами и письмо 60–80 слов — десять шагов, около пятнадцати минут; старт не с B1, а с уровня последнего завершённого теста или среза; виденные задания не повторяются; письмо оценивает экзаменатор, пять осей и уровень — как в тесте; ошибки уходят карточками в журнал. Тест уровня и срез не мешают друг другу: пока идёт один, второй не начать (`assessment_busy` 409 с видом идущего теста), карточка «Тест уровня» срезы не показывает. Миграция 0016: `assessments.adaptive_count` (NULL у старых строк читается как 12), `assessments.program_day_id`, индекс по виду.
- Сравнение с прошлым (`compare`): сводный балл, уровень и каждая ось против предыдущего завершённого теста или среза (исходный срез 29.10 — первая точка), вывод одной строкой без украшений: «Уровень вырос: B1 → B2, сводный балл +9 к исходному срезу от 2026-10-29 (53 → 62)», «Уровень не изменился — B1; сводный балл +3 — в пределах погрешности короткого теста», «Уровень тот же — B1, но сводный балл вырос на 5; до B2 осталось 2», «Уровень снизился: …». Разница меньше `SIGNIFICANT_DELTA = 5` погрешностью и называется; оси, выросшие или просевшие на 5 и больше, перечислены отдельно. Сравнение приходит в `comparison` у любого завершённого теста с оценкой (у теста уровня тоже — против исходного среза), на экране показано у среза.
- Привязка к программе (`functions/_lib/checkpoint.ts`): в день `format = checkpoint` срез привязывается к дню, после оценки день → `done` со сводным баллом; оставшиеся `planned`-дни программы пересобираются по свежему профилю ошибок (ошибки и оси среза, карточки) — «корректировка программы» из концепта; пройденные дни и сам день среза остаются, пересчёт без изменения балла программу второй раз не трогает. Срез можно пройти и вне плана в любой день — тогда ни день программы, ни программа не трогаются (пересобрать можно кнопкой в карточке «Программа»). Причина у следующего среза в программе: «сравнение с контрольным срезом от …».
- Главный экран: срез становится новой базой готовности (строка «База … — контрольный срез …», занятия считаются после него); день среза в серии и в минутах недели (по заданиям от выдачи до ответа); в плане недели день среза больше не «позже», а обычный день плана (пройдено с баллом / сегодня / пропущено — серию пропуск не рвёт, как и репетиция); кнопка дня на главном ведёт по формату: занятие, репетиция или срез. Карточка «Сегодня» в день среза отсылает к карточке «Контрольный срез».
- API: `GET /api/checkpoint` — сегодня ли срез по программе, день, следующий запланированный срез, активный или последний пройденный срез (со сравнением, днём и `programAdjusted`), пределы `total 10 / adaptive 8 / significant 5`; `POST /api/checkpoint/start` — начать или продолжить; `POST /api/checkpoint/answer {attemptId, answer}` — ответ, после последнего — оценка, сравнение, день программы, пересборка; `POST /api/checkpoint/score {force}` — пересчитать; `POST /api/checkpoint/abandon` — бросить. Ошибки те же, что у теста, плюс `assessment_busy` 409. `lesson_unavailable` в день среза теперь ссылается на маршрут среза. Дымовая проверка — аннотация `checkpoint` в шаге Deep check.
- Экраны: карточка «Контрольный срез» на главном (после «Репетиции интервью»): «сегодня по программе» / «следующий <дата>» / «вне плана», описание формата, начать / продолжить / начать заново, итог последнего среза с уровнем, баллом, днём программы и выводом сравнения; экран среза — тот же экран теста (`Assessment kind=checkpoint`: те же горячие клавиши, микрофон и озвучка задания) с заголовком «Контрольный срез»; результат — блок «Сравнение с прошлым тестом» сразу после уровня: вывод, балл до → после с разницей (мята — рост, коралл — просадка, приглушённо — погрешность), оси с разницей, выросшие и просевшие; затем лестница, радар, письмо, примеры ошибок; строка о пересборке программы.
- Тесты `tests/checkpoint.test.ts` (9): план и `kindAt/estimateLevel` на восьми заданиях, все ветви сравнения, ход по плану (уровень старта, 10 шагов, день → done, сравнение, пересборка программы и её идемпотентность, готовность и серия на главном), вне плана (программа не тронута, abandon), блокировка другим тестом и обратно, маршруты API без cookie и целиком, D1-хранилище по виду на миграциях. Тесты главного экрана обновлены (день среза — план). Playwright на dist с route-моком: карточка, ход среза, результат со сравнением, карточка после среза, план недели «пройдено · 92», экран на телефоне в тёмной теме.

Неверное исправление — карточка показывает исходное предложение с ошибкой и эталон задания; неверный выбор варианта — предложение с выбранным и с верным словом; правило — объяснение задания. Ошибки письма, найденные экзаменатором, — цитата, правка и его строка-правило, до трёх с одного письма; тему ошибки экзаменатор теперь называет сам из справочника тем карточек (поле `topic` в схеме и подсказке `scoring.ts`), в занятии без темы берётся тема дня. Чтение карточек не даёт. Та же ошибка (по тексту «как написано») не заводит вторую карточку; если такая карточка уже погашена — она возвращается в оборот на завтра с обнулённой серией. Ключ источника (`origin`: попытка теста или шаг занятия, для письма — с номером ошибки) и частичный уникальный индекс не дают пересчёту теста задвоить карточки. Новые карточки получают срок на завтра — в сегодняшнем занятии не всплывают.

В разборе шага — состояние карточки (`card`: срок, серия, сколько осталось до гашения, погашена ли) и `newCards` — сколько карточек завёл шаг. Темы «профессиональная лексика», «регистр рецензента» и «орфография» идут в ось словаря, остальные — в грамматику. Беглость речи до голосовой реплики (4.2) не оценивается и остаётся пустой; сводный балл считается по имеющимся осям с весами 0,3 / 0,2 / 0,2 / 0,2 / 0,1 и перенормировкой.
- Письмо оценивает модель-экзаменатор по рубрике и образцу задания из банка (эталон), по четырём осям в той же шкале, с русским резюме, списком реальных ошибок из текста (цитаты проверяются на присутствие в тексте ученика — выдуманные отбрасываются) и переписанным вариантом. Оценка хранится в `attempts.detail` (JSON), письмо получает `score` и `feedback`. Если модель не ответила, тест всё равно завершается: оси считаются по остальным заданиям, причина — в `scoring_note`, на экране кнопка «Оценить письмо снова».
- Уровень CEFR — ступень, в которую попал сводный балл, с запасом 10 баллов от низа ступени (пороги 35 / 60 / 85): чередование «верно на B1 / неверно на B2» даёт B1, а не B2. Оси пишутся в колонки `assessments.grammar … fluency`, сводный балл — в `overall`. Миграция 0007 добавляет `assessments.overall`, `scored_at`, `scoring_note` и `attempts.detail`.
- API: ответ на последнее задание и `GET /api/assessment` возвращают `result` — оси, сводный балл, уровень, лестницу (пороги ступеней и остаток до следующей), до трёх примеров ошибок и сводку письма; `POST /api/assessment/score` `{force?}` пересчитывает последний завершённый тест (для тестов, пройденных до этой версии, и повторной оценки письма); без завершённого теста — `assessment_none` 404. Ключи заданий наружу по-прежнему не уходят.
- Экран результата: уровень и сводный балл, лестница A2–C1 с отметкой балла и порогами ступеней, радар пяти осей (неоценённая ось — пунктиром) и полосы по осям, резюме письма с переписанным вариантом, три примера собственных ошибок (как написано — как надо — правило одной строкой; сначала из письма, затем неверные исправления и выборы варианта). Карточка «Тест уровня» показывает уровень, балл и пять осей, кнопки «Открыть разбор» и «Пройти заново». Дымовая проверка нового маршрута в workflow.


## 0.6.0 — 2026-10-30
- Адаптивный тест уровня (задача 2.5). Модуль `functions/_lib/assessment.ts`: четырнадцать заданий — двенадцать на грамматику и лексику (выбор варианта, на каждой третьей позиции исправление ошибки), затем чтение с двумя вопросами и письмо 60–80 слов. Тест начинается с B1; верный ответ поднимает сложность на ступень, неверный опускает, в пределах A2–C1. Чтение и письмо даются на уровне, к которому подошёл ученик.
- Задания берутся из банка (только принятые проверкой): нужный уровень, затем соседние; темы последних трёх заданий не повторяются; задание, которое пользователь уже видел в любом тесте, не показывается снова. Если в банке пусто на всех уровнях, модель пишет задание прямо во время теста через обычный конвейер генерации с проверкой; если и это не удалось — ошибка `bank_empty`.
- Прерывание и продолжение: каждое выданное задание сразу записывается в `attempts` без ответа, повторный «Начать/Продолжить» возвращает то же задание; «Начать заново» помечает тест `abandoned`. Ответы проверяются сравнением с эталоном: буква варианта, две буквы чтения (0/50/100), исправленное предложение без учёта регистра и знаков (неизменённое — неверно). Письмо принимается в границах 30–200 слов и только сохраняется — оценка по пяти осям и экран результата — задача 2.6.
- Предварительный уровень по адаптивной части: самый высокий уровень, на котором не меньше двух ответов и верна хотя бы половина; иначе A2.
- API: `GET /api/assessment` (состояние: активный тест с текущим заданием без ключа, объяснения, рубрики и уровня, или последний завершённый с уровнем), `POST /api/assessment/start`, `POST /api/assessment/answer` `{attemptId, answer}`, `POST /api/assessment/abandon`; ошибки `assessment_none`, `assessment_stale`, `answer_invalid` (с причиной empty/format/too_short/too_long), `bank_empty`. Миграция 0006 добавляет в `assessments` колонки `status`, `current_level`, `updated_at`, в `attempts` — `position`, `level`, `answered_at`, и индексы.
- Экран теста: полоса прогресса, одно задание на экране, варианты кнопками (клавиши 1–4 и Enter), исправление в моноширинном поле с подставленным предложением, текст чтения блоком с двумя вопросами, письмо со счётчиком слов (Ctrl+Enter отправляет), «Прервать — продолжу позже». Карточка «Тест уровня» на главном экране: начать, продолжить, начать заново, предварительный уровень после завершения. Дымовая проверка новых маршрутов в workflow.

## 0.5.0 — 2026-10-30
- Банк заданий для теста уровня (задача 2.4). Модуль `functions/_lib/items.ts`: тринадцать тем из программы концепта (артикли, времена, союзы и инверсия, квантификаторы, глагольные конструкции, модальные, условные, пассив, предлоги, относительные, регистр рецензента, орфография, профессиональная лексика), четыре вида заданий (выбор варианта с пропуском, исправление одной ошибки, чтение 60–220 слов с двумя вопросами на подтекст, письмо 60–80 слов с рубрикой и образцом), уровни A2–C1 с описанием каждой ступени в подсказке модели. Задания пишутся в домене пользователя — специальность, отрасль, целевая позиция и термины из профиля резюме.
- Второй прогон-проверка: каждое задание отдельно отправляется модели-экзаменатору. Для выбора варианта и чтения ключ скрыт — экзаменатор решает вслепую; для исправления и письма он видит ключ и ищет изъяны. Задание принимается (`verified`), если ключ совпал с решением, независимая оценка уровня расходится не больше чем на ступень и изъянов нет; иначе — `rejected` с причиной одной строкой. Отклонённые хранятся для разбора и защиты от повторов. До экзаменатора задание проходит структурную проверку (ровно четыре разных варианта, пропуск `___`, длина текста, объяснение и рубрика по-русски, образец в диапазоне слов) и отсев дублей по отпечатку формулировки — внутри ответа и против банка.
- API: `GET /api/items/topics` (справочник), `GET /api/items/stats` (сводка по уровню, виду и статусу), `GET /api/items/bank?level&topic&kind&status` (задания с ключами и заметками проверки — для владельца банка; тест уровня в 2.5 будет отдавать задания своим маршрутом без ключей), `POST /api/items/generate` `{kind, level, topic, count ≤ 6}`; ошибки `items_invalid`, `items_failed`.
