# Изменения

## 0.5.0 — 2026-10-30
- Банк заданий для теста уровня (задача 2.4). Модуль `functions/_lib/items.ts`: тринадцать тем из программы концепта (артикли, времена, союзы и инверсия, квантификаторы, глагольные конструкции, модальные, условные, пассив, предлоги, относительные, регистр рецензента, орфография, профессиональная лексика), четыре вида заданий (выбор варианта с пропуском, исправление одной ошибки, чтение 60–220 слов с двумя вопросами на подтекст, письмо 60–80 слов с рубрикой и образцом), уровни A2–C1 с описанием каждой ступени в подсказке модели. Задания пишутся в домене пользователя — специальность, отрасль, целевая позиция и термины из профиля резюме.
- Второй прогон-проверка: каждое задание отдельно отправляется модели-экзаменатору. Для выбора варианта и чтения ключ скрыт — экзаменатор решает вслепую; для исправления и письма он видит ключ и ищет изъяны. Задание принимается (`verified`), если ключ совпал с решением, независимая оценка уровня расходится не больше чем на ступень и изъянов нет; иначе — `rejected` с причиной одной строкой. Отклонённые хранятся для разбора и защиты от повторов. До экзаменатора задание проходит структурную проверку (ровно четыре разных варианта, пропуск `___`, длина текста, объяснение и рубрика по-русски, образец в диапазоне слов) и отсев дублей по отпечатку формулировки — внутри ответа и против банка.
- API: `GET /api/items/topics` (справочник), `GET /api/items/stats` (сводка по уровню, виду и статусу), `GET /api/items/bank?level&topic&kind&status` (задания с ключами и заметками проверки — для владельца банка; тест уровня в 2.5 будет отдавать задания своим маршрутом без ключей), `POST /api/items/generate` `{kind, level, topic, count ≤ 6}`; ошибки `items_invalid`, `items_failed`. Миграция 0005 добавляет в `items` колонки `status`, `check_note`, `checked_level`, `verified_at`, `fingerprint`, `source` и индексы.
- Карточка «Банк заданий» на главном экране после разбора резюме: таблица принятых заданий по уровням и видам, выбор уровня, вида, темы и количества, кнопка «Пополнить банк», список результата с пометкой принято/отклонено и заметкой проверки, просмотр имеющихся. Дымовая проверка новых маршрутов в workflow.

## 0.4.0 — 2026-10-30
- Анкета знакомства из шести вопросов: целевая позиция (подставляется из разбора резюме), дата собеседования (необязательна, не раньше сегодняшнего дня в поясе пользователя, не дальше двух лет), формат (письменный тест, видеозвонок, ИИ-интервью, пока не известно), минуты в день (10–60 на экране, 5–180 в API), часовой пояс (список браузера со смещением UTC, по умолчанию — пояс браузера) и родной язык. Открывается сама после разбора резюме, её можно отложить и вернуться кнопкой «Дальше — шесть вопросов».
- API `PUT /api/onboarding`: проверка ответов на сервере, ошибка `onboarding_invalid` с полем и причиной; часовой пояс пишется в `users.tz`, остальное — в `profiles`. Миграция 0004 добавляет колонки `native_language` и `onboarded_at`. После анкеты повторный разбор резюме не затирает целевую позицию, заданную пользователем.
- Карточка «Подготовка»: цель, дата с обратным отсчётом («через 24 дня»), формат, нагрузка, пояс, язык; кнопка «Изменить ответы». Карточка «Что я понял из резюме» ведёт к анкете, пока она не заполнена. Дымовая проверка нового маршрута в workflow.

## 0.3.5 — 2026-10-30
- Разбор резюме в проде падал (модель не возвращала разбираемый JSON). Включён JSON-режим Workers AI (`response_format: json_schema` со схемой профиля), подсказка переписана без псевдо-JSON, который модель копировала; ошибка теперь содержит начало ответа модели. `/api/health?deep=2` прогоняет полный разбор встроенного тестового резюме; дымовой тест выводит результат.

## 0.3.4 — 2026-10-30
- Диагностика разбора резюме: при ошибке модели API возвращает `detail`, экран показывает текст ошибки сервера; `/api/health?deep=1` делает короткий вызов встроенной модели (`ai_chat`), дымовой тест выводит его предупреждением.

## 0.3.3 — 2026-10-30
- Кнопка «Установить приложение» показывается и до входа — раньше она была только на экране вошедшего пользователя, а войти без ключа почты нельзя.

## 0.3.2 — 2026-10-30
- Исправление: кнопка «Установить приложение» была всегда неактивна. В манифесте была только SVG-иконка — Chrome не считал приложение устанавливаемым и не присылал `beforeinstallprompt`. Добавлены PNG-иконки 192 и 512 (и maskable), `apple-touch-icon`. Кнопка больше не блокируется: если браузер не предлагает установку сам (Safari, Firefox), показывает инструкцию для этого браузера; в установленном приложении пишет «Приложение установлено».
- В дорожную карту: 3.7 горячие клавиши; 4.2 уточнена — голосовой ответ на любой вопрос.

## 0.3.1 — 2026-10-30
- Исправление: в проде PDF не читался — `/api/health?deep=1` отвечал «PDF.js could not be resolved: Cannot set properties of undefined (setting '_isSameOrigin')». Причина — esbuild 0.17 внутри wrangler 3.x: при сборке Functions он выносил приватные статические поля pdf.js из класса, и статический блок обращался к ещё не объявленной переменной. Wrangler поднят до 4.x (esbuild 0.28), `@cloudflare/workers-types` — до 5.x; извлечение PDF проверено в локальном workerd.

## 0.3.0 — 2026-10-30
- Загрузка резюме: PDF (pdf.js через `unpdf`), DOCX (собственный разбор zip и `word/document.xml`, без зависимостей) и обычный текст; тип определяется по сигнатуре файла, лимит 8 МБ, файл не сохраняется — только извлечённый текст.
- Профиль через модель: специальность, отрасль, стаж, целевая позиция, до двадцати английских терминов специальности и короткое резюме «что я понял». Ответ модели проверяется и нормализуется, при неверном JSON — одна повторная попытка; если разбор не удался, текст остаётся и доступен повтор.
- API `GET /api/profile`, `POST /api/resume` (multipart `file` или JSON `{text}`), `POST /api/resume/analyze`; коды ошибок `resume_unsupported`, `resume_too_large`, `resume_unreadable`, `resume_no_text`, `resume_too_short`, `profile_failed`. Миграция 0003 добавляет в `profiles` колонки `resume_name`, `resume_at`, `summary`.
- Экран «Резюме» (файл перетаскиванием или вставка текста) и карточка «Что я понял из резюме» с терминами и заменой резюме; дымовая проверка новых маршрутов в workflow.

## 0.2.0 — 2026-10-30
- Вход по почте с одноразовым кодом, без пароля: таблицы `login_codes` и `sessions` (миграция 0002), API `/api/auth/request`, `/api/auth/verify`, `/api/auth/logout`, `/api/me`; cookie-сессия HttpOnly на 30 дней; коды и токены хранятся только хэшами, лимит — три кода за пятнадцать минут и пять попыток на код.
- Письмо с кодом через Resend (секрет `RESEND_API_KEY`, отправитель `MAIL_FROM`); без ключа API честно отвечает `mail_not_configured`, в `/api/health` добавлено поле `mail`.
- Экран входа: почта → код → учётная запись; состояние сессии в шапке, выход.

## 0.1.0 — 2026-10-30
- Каркас приложения: PWA на React и Vite, API на Hono (Pages Functions), схема D1, модуль провайдеров моделей (встроенная Workers AI и режим «свой ключ»), деплой через GitHub Actions, страница состояния.
